# Profile cards

The introduction is a Linux login-style card at `assets/intro.svg`, sharing the
existing frame, 800px width, and foreground color. It shows a welcome banner,
website/GitHub links, a two-column profile summary, and the original greeting
and bio. Below the bio, a DDD advocacy message shows a white "DDD:" label,
pink "Dopagaki Driven Development", and "I love DDD!".
The terminal then illustrates typing `curl -fsSL https://chatgpt.com/codex/install.sh | sh`
at a green `nekosanq@github:~$` prompt. A compact version of the user's installer
transcript shows installation, download, success, `Start Codex now? [y/N] y`,
and launch. This is a decorative SVG animation; generation never executes the
command or downloads an installer.
It plays once on load, then rests at a fresh prompt. Reduced-motion settings
show the completed static state, as do renderers without animation support.
Edit `scripts/intro.ts` and run `npm run generate:intro` to update it without a token.
The profile summary shows Country (`Oita, Japan`) and Language (`Japanese,
English (almost read-only)`). Age is calculated from January 11, 2007 using the
current date in `Asia/Tokyo` at SVG generation time, and refreshed by the daily
workflow. The website remains in the introductory links, outside the summary.

Status and Skills are separate SVG cards generated by TypeScript. Text,
numbers, and icons use the same light foreground (`#e6edf3`) as the supplied
README reference, including Status values. The existing card background is
`#0d1117`, Skills badges are `#151b23`, and borders are `#3d444d`. Both share
the theme, frame, heading, and typography helpers in `scripts/cards.ts`.
Status places General, Repositories, and Contributions side by side in one
horizontal row, with vertical dividers between the three columns and a full-width
language bar below them. Skills retains its compact, square badges in four groups.
The SVGs contain all icons directly and require no external image service.
The README displays the cards directly, without separate Status or My Skills
headings; each card already has its own title.

Website and Twitter / X use two compact 396px cards with the same frame, header,
icons, and colors. README anchors wrap each image so the entire card is clickable
on GitHub. The Website and Twitter destinations are kept in those README anchors.
Edit `scripts/links.ts` for card text, then run `npm run generate:links` to rebuild
both images without a token. The daily workflow also regenerates these cards.

## Updating

The **Update profile stats** GitHub Actions workflow runs daily at 12:23 JST
(03:23 UTC), on generator changes pushed to `main`, and manually via
**Actions → Update profile stats → Run workflow**. Scheduled runs may be delayed
by GitHub. It commits changed SVGs and the Status block using the built-in `GITHUB_TOKEN`;
no personal access token secret is required. The workflow updates introduction,
Status, and Skills SVGs and only the README block between `stats:start` and `stats:end` markers.
Branch rules must allow this bot
to push to `main` for automatic updates to be saved.

For local generation, use Node.js 24 or later:

```powershell
npm ci
npm run check
npm test
$env:GITHUB_TOKEN = '<your GitHub token>'
npm run generate
```

Skills is edited in `scripts/skills.ts`; it lists 45 technologies, including
Kotlin, SQLite, Zabbix, Nginx, WireGuard, and draw.io. Use `npm run generate:skills` to
regenerate just that card without a token. Available brand logo paths from `simple-icons` are embedded directly in
the SVGs. Other entries use matching white line icons.

`GH_TOKEN` is also supported. `PROFILE_USERNAME` defaults to `NekosanQ`.
Tokens are used only for API requests and are never included in the images.

## What the numbers mean

- General shows the year joined, followers, following, and the most starred and
  most forked owned public non-fork repositories. Long names are shortened
  visually; full names remain in the SVG's accessible description.
  Empty results show a dash.
- Repositories shows **Non-forks / All** (including forks) for each metric:
  repository count, received stars, received forks, watchers,
  template repositories, and archived repositories. Archived repos are included.
- Commits, pull requests, issues, and PR reviews use GitHub's contribution counts for the
  past year (the default `contributionsCollection` window), not lifetime totals.
  GitHub's contribution attribution rules apply; this is not every Git commit.
- Contributed to counts repositories with commit contributions in that same year.
- Language distribution sums GitHub's detected language bytes across owned public
  non-fork repositories. The seven largest languages are listed. Percentages use
  **all** detected languages; the remainder is grouped as Other. The segmented
  bar and legend use the language colors supplied by GitHub. Missing or invalid
  colors and Other use gray. The bar's segment widths use the same byte totals
  as the legend percentages.
  Code size does not measure proficiency or time spent.
- The workflow token reads public activity. Local tokens with broader access
  can change the contribution counts returned by GitHub; use the workflow for
  consistent public stats.

Repository results are paginated. An API error fails generation before the
existing cards are written, leaving the last successful images available.
The cards include accessible titles and descriptions and contain no scripts,
external fonts, or external images.
The README displays `assets/github-stats.svg` and `assets/skills.svg`.
A standalone language card is also generated at `assets/top-languages.svg`.
